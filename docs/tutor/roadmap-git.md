# แผนที่วิชา Git & GitHub ของ LnwNetwork (สร้างจากสคริปต์ ห้ามแก้มือ)

เรียงตามลำดับที่ผู้เรียนเรียน ผู้เรียนรู้เรื่องในบทก่อนหน้าทั้งหมด รวมบทที่เรียนอยู่ตอนนี้ แต่ยังไม่รู้เรื่องในบทที่อยู่หลังบทนั้น

"สอน:" คือศัพท์ที่บทนั้นสอนเป็นครั้งแรก / "ต่อจาก:" คือบทก่อนหน้าที่บทนั้นต้องใช้ความรู้

## ภาค 0 · เริ่มจากศูนย์

- ทำไมต้องมี Git (ปุ่มเซฟในเกม กับสมุดจดของร้านค้า) — พร้อมเรียน
  - สอน: Git, Version control
- ตระกูล Git ต่างกันยังไง (สมุดบัญชี วิธีเขียนลงสมุด และตู้เซฟกลาง) — พร้อมเรียน
  - สอน: Command line, Git Bash, GitHub Desktop, GitHub, GitLab
  - ต่อจาก: ทำไมต้องมี Git · Git คือตัวจดจุดเซฟของงาน บทนี้ดูว่าตัวอื่นที่ชื่อคล้าย ๆ กันทำหน้าที่อะไร
- repository กับ commit (เซฟเกมแต่ละช่อง กับสมุดบันทึกประจำร้านที่จดทุกครั้งที่เซฟ) — พร้อมเรียน
  - สอน: Repository, Commit
  - ต่อจาก: ทำไมต้องมี Git · Git เหมือนปุ่มเซฟของงาน จดไว้ว่าใครเซฟเมื่อไร และย้อนกลับได้ บทนี้ดูว่าปุ่มเซฟนั้นทำงานยังไง
  - ต่อจาก: ตระกูล Git ต่างกันยังไง · เราสั่ง Git ด้วยการพิมพ์ใน Git Bash บทนี้จะพิมพ์คำสั่งจริงชุดแรก
- git add (เลือกของใส่กล่องก่อนปิดผนึก) — พร้อมเรียน
  - สอน: Staging area
  - ต่อจาก: repository กับ commit · commit คือจุดเซฟ และก่อน commit ต้อง git add บทนี้อธิบายว่า git add ทำอะไร ทำไมต้องมีขั้นนี้
- ในเครื่องกับบนเน็ต (สมุดบัญชีของแต่ละร้าน กับตู้เซฟกลางที่ถ่ายสำเนาไปมา) — พร้อมเรียน
  - สอน: Remote, origin, Clone, Push, Pull
  - ต่อจาก: repository กับ commit · commit คือจุดเซฟที่อยู่ในเครื่องเรา บทนี้ดูว่าจะเอาจุดเซฟไปให้เพื่อนยังไง
  - ต่อจาก: git add · ก่อน commit ต้อง git add ใส่กล่องก่อน บทนี้จะใช้ทั้งสองคำสั่งต่อกับการส่งงาน

## ภาค 1 · ทำงานคู่กับเพื่อน

- branch (แยกกันทำคนละห้อง ห้องใครห้องมัน สมุดฉบับหลักที่ทุกคนใช้ไม่ถูกแตะ จนกว่าจะถึงตอนรวมงาน) — พร้อมเรียน
  - สอน: Branch, HEAD
  - ต่อจาก: repository กับ commit · commit ต่อกันเป็นเส้นจุดเซฟ บทนี้จะเห็นว่าเส้นนั้นแตกเป็นสองสายได้
  - ต่อจาก: ในเครื่องกับบนเน็ต · เพื่อนทำงานอยู่อีกเครื่อง บทนี้ดูว่าจะไม่ให้งานของเราและเพื่อนปนกันยังไง
- Pull Request (ส่งการบ้านให้เพื่อนอ่านทวนก่อนส่งครู ไม่ใช่ส่งครูเลยแล้วค่อยรู้ว่าผิด) — พร้อมเรียน
  - สอน: Pull Request, Review, Merge
  - ต่อจาก: branch · งานใหม่ทำในสาย branch ของตัวเอง บทนี้ดูว่าทำเสร็จแล้วจะเอาเข้า main ยังไงให้เพื่อนตรวจก่อน
  - ต่อจาก: ในเครื่องกับบนเน็ต · ต้อง push ขึ้น GitHub และ pull ลงเครื่อง บทนี้ใช้ทั้งสองคำสั่งกับสายที่แยกออกมา
- merge กับ conflict (เย็บร่างจากห้องแยกกลับเข้าสมุดฉบับหลัก ถ้าสองคนเขียนช่องเดียวกันคนละแบบ คนเย็บต้องเลือกเอง) — พร้อมเรียน
  - สอน: Conflict, Merge commit
  - ต่อจาก: Pull Request · บนเว็บ GitHub มีปุ่ม Merge pull request บทนี้ดูว่าในเครื่องเราทำเรื่องเดียวกันด้วยคำสั่งยังไง และเกิดอะไรถ้างานชนกัน
  - ต่อจาก: git add · แก้ conflict เสร็จต้อง git add แล้วค่อย commit บทนี้ใช้สองคำสั่งนี้ปิดงาน
- วิธีที่คนนิยมใช้ (ร้านอาหารที่มีเมนูหลักสั่งได้เสมอ สูตรใหม่ลองในครัวหลังร้านก่อน และของส่วนตัวไม่เอาออกมาวางหน้าร้าน) — พร้อมเรียน
  - สอน: GitHub Flow, .gitignore, Commit message
  - ต่อจาก: Pull Request · GitHub Flow คือขั้นตอน Pull Request ที่เพิ่งเรียน เรียงต่อกันเป็นวงรอบประจำ
  - ต่อจาก: merge กับ conflict · ขั้นรวมงานของวงรอบ ใช้ merge ที่เพิ่งเรียน และบางครั้งเจอ conflict
  - ต่อจาก: repository กับ commit · ข้อความ commit คือข้อความหลัง -m ที่เขียนตอน commit บทนี้ดูว่าเขียนยังไงให้ดี

## ภาค 2 · ใช้จริง

- push งานจริงครั้งแรก (เปิดตู้เซฟกลางของห้อง เอาลิงก์ตู้มาจดไว้ในมือถือ ส่งของใส่ตู้ครั้งแรกต้องโชว์บัตรกับเจ้าหน้าที่ แล้วให้กุญแจเพื่อนมาหยิบของได้) — พร้อมเรียน
  - สอน: Collaborator, GCM
  - ต่อจาก: ในเครื่องกับบนเน็ต · บทนี้พิมพ์ git push กับ git clone จริงเป็นครั้งแรก ต่อจากภาพเครื่องเรา GitHub และเครื่องเพื่อนที่เพิ่งเรียน
  - ต่อจาก: repository กับ commit · ต้องมีจุดเซฟอย่างน้อยหนึ่งอันในเครื่องก่อน ถึงจะมีอะไรให้ push
  - ต่อจาก: วิธีที่คนนิยมใช้ · ชื่อสาย main ที่ทีมใช้เป็นสายหลัก และ .gitignore กันของลับไม่ให้ขึ้นไปกับ push
