# วิชาที่สอง: Git & GitHub ทำงานเป็นทีม — เอกสารออกแบบ

วันที่: 2026-10-27
สถานะ: ร่าง รอผู้ใช้อนุมัติ
ต่อจาก: `2026-10-27-foundations-first-design.md` (วิธีสอน กฎ "พื้นฐานก่อน" ข้อ 3–4 และกฎภาพเคลื่อนไหวข้อ 3.1 ใช้กับวิชานี้ทุกข้อ) และ spec เดิม `2026-10-24-ccna-learning-app-design.md` ข้อ 7 (กฎการเขียนเนื้อหา)

## 1. ทำไม

ผู้ใช้กำลังจะ push code ขึ้น GitHub เป็นครั้งแรก และทำงานคู่กับเพื่อน แต่ยังไม่รู้ว่า:
- ต้องทำยังไง
- ทำแบบไหนถึงจะดี และคนส่วนใหญ่นิยมทำกันแบบไหน
- GitHub มีประโยชน์ยังไง
- แต่ละคำสั่งทำงานยังไงเบื้องหลัง ("ยังไม่เข้าใจหลักการทำงานของแต่ละคำสั่งเลย")
- ทำไมถึงมีหลายตัว (git, Git Bash, GitHub Desktop, GitHub) และแต่ละตัวต่างกันยังไง

ผู้ใช้บอกว่าเรียนให้เข้าใจก่อนได้ ไม่ต้องรีบ push งานจริง

**เกณฑ์ความสำเร็จ (ผู้ใช้เห็นด้วย):** push งานจริงครั้งแรกกับเพื่อนได้เอง และอธิบายได้ว่าแต่ละคำสั่งทำอะไรเบื้องหลัง

## 2. สิ่งที่ผู้ใช้ตัดสินใจแล้ว

1. เป็นหมวดใหม่ในแอป LnwNetwork ใช้วิธีสอนแบบเดิมทั้งหมด: เช็กพื้นฐาน → คลิป → ภาพเคลื่อนไหวพร้อมแถบชีวิตจริง → ลองกดเอง → ลองเล่น → คำถาม
2. ไล่จากศูนย์จริงๆ: เริ่มจาก "ทำไมต้องมี Git" ก่อนจะสอนคำสั่งใดๆ
3. ฝึกในแบบจำลองในแอปก่อน (พิมพ์ผิดแล้วไม่มีอะไรพัง) แล้วค่อยไปพิมพ์คำสั่งจริงใน Git Bash บนเครื่องตัวเอง
4. มีบทที่อธิบายตระกูล Git ว่า git, Git Bash, GitHub Desktop และ GitHub ต่างกันยังไง และทำไมต้องมีหลายตัว
5. ทุกบทมีคลิป YouTube ภาษาไทยที่อธิบายเข้าใจง่ายแนบไว้
6. **ใช้ Git Bash เป็นหลัก** ตอนทำงานจริงกับเพื่อน บทเรียนและการฝึกจึงเน้นการพิมพ์คำสั่ง ส่วน GitHub Desktop อธิบายในบทตระกูล Git ว่าคืออะไร และกดปุ่มไหนตรงกับคำสั่งไหน แต่ไม่ได้สอนเป็นหลัก

## 3. เนื้อหา (ร่าง roadmap ผู้ใช้บอกว่า "ไม่ผิด")

**ภาค 0 · เริ่มจากศูนย์**
1. ทำไมต้องมี Git: ไฟล์ `งาน_final_จริงๆ_v3.docx` และงานที่ส่งกันทาง LINE แล้วทับกัน
2. ตระกูล Git ต่างกันยังไง
   - **Git** = โปรแกรมจดประวัติงาน ทำงานในเครื่อง
   - **Git Bash** = หน้าต่างพิมพ์คำสั่งบน Windows
   - **GitHub Desktop** = แอปที่มีปุ่มกดแทนการพิมพ์คำสั่ง
   - **GitHub** = เว็บที่เก็บงานบนอินเทอร์เน็ต ให้เพื่อนเข้ามาดูและแก้ด้วยกันได้
   - ต้องตอบให้ได้ว่าทำไมต้องมีหลายตัว (แยกกันระหว่างตัวจดประวัติ / วิธีสั่งงาน / ที่ฝากงานออนไลน์) และบอกด้วยว่ามีเว็บแบบ GitHub เจ้าอื่นอีก (เช่น GitLab)
3. repository กับ commit = เซฟเกม ย้อนกลับไปจุดเซฟไหนก็ได้
4. `git add` (staging) = เลือกของใส่กล่องก่อนปิดผนึก
5. ในเครื่องกับบนเน็ต: `clone` / `push` / `pull`

**ภาค 1 · ทำงานคู่กับเพื่อน**
6. branch = แยกกันทำคนละห้อง ไม่ทับกัน
7. Pull Request = ขอให้เพื่อนตรวจงานก่อนรวม
8. merge และ conflict = งานชนกันแล้วแก้ยังไง
9. วิธีที่นิยมใช้กัน (GitHub Flow), `.gitignore`, การเขียน commit message ที่ดี

**ภาค 2 · ใช้จริง**
10. push โปรเจกต์จริงครั้งแรก, เชิญเพื่อนเป็น collaborator, การล็อกอินตอน push

ทุกบททำตามกฎ "พื้นฐานก่อน" (spec foundations-first ข้อ 4): บทไหนใช้ศัพท์ก่อนบทที่สอนไม่ได้ ตัวตรวจอัตโนมัติจับได้ และทุกคำสั่งต้องบอกว่า "ถ้าไม่พิมพ์คำสั่งนี้จะเกิดอะไร"

## 4. ภาพเคลื่อนไหว

ใช้เครื่องเล่นฉากแบบใหม่ (v2) และกฎ 10 ข้อของ spec foundations-first ข้อ 3.1 ภาพหลักของวิชานี้:
- **ประวัติงานเป็นเส้นจุดเซฟ** (commit เป็นจุดบนเส้น branch เป็นเส้นแยก merge เป็นเส้นที่มาบรรจบกัน)
- **สามที่ของไฟล์**: โฟลเดอร์งาน → กล่องรอปิดผนึก (staging) → ประวัติ (repository) เห็นไฟล์ย้ายที่ตามคำสั่ง
- **เครื่องเรา / GitHub / เครื่องเพื่อน** วางคู่กัน เห็นว่า push, pull และ clone ส่งอะไรไปทางไหน
- **"สิ่งที่แต่ละที่รู้"** (กฎ 3.1.4): แต่ละเครื่องมีเส้นประวัติของตัวเอง เห็นได้ชัดว่าเครื่องเพื่อนยังไม่มี commit ใหม่จนกว่าจะ pull

## 5. ฝึกในแอป (จำลอง)

- ช่องพิมพ์คำสั่งจำลอง รองรับเฉพาะคำสั่งที่สอนแล้วถึงบทนั้น (`init`, `status`, `add`, `commit`, `log`, `branch`, `switch`/`checkout`, `merge`, `clone`, `push`, `pull`) พิมพ์แล้วภาพประวัติ สามที่ของไฟล์ และเครื่องเพื่อนเปลี่ยนตามทันที
- พิมพ์คำสั่งผิดหรือยังไม่ได้สอน ต้องอธิบายเป็นภาษาไทยง่ายๆ ว่าทำไมใช้ไม่ได้
- มีโจทย์ต่อบท (เช่น "ทำ commit แรก", "เพื่อน push มาแล้ว ดึงงานของเพื่อนลงมา", "แก้ conflict ให้ได้") และโจทย์แบบ "อะไรผิด ลองซ่อม"
- จำลอง "เพื่อน" ที่ทำ commit ได้เอง เพื่อให้ฝึก pull และ conflict ได้คนเดียว
- จบแต่ละภาคมีขั้น "ลองของจริง": รายการคำสั่งที่ให้ไปพิมพ์ใน Git Bash จริง พร้อมผลที่ควรเห็น

## 6. คลิป

ทุกบทมีคลิป YouTube ภาษาไทยที่อธิบายเข้าใจง่ายเป็นคลิปหลัก ต้องเช็กว่าฝังในแอปได้ (`playableInEmbed`) และบอกไว้ในรายงานว่าคลิปไหนยังไม่มีคนดูเนื้อหาจริง ถ้าหาคลิปไทยที่ตรงบทไม่ได้ ให้ใช้คลิปที่ใกล้ที่สุด พร้อม `noteTh` บอกว่าดูช่วงไหน

- เสียงพากย์ใช้ F5-TTS เดิม

## 8. ไม่ทำในรอบนี้

- ไม่ต่อกับ GitHub จริงจากในแอป ไม่ล็อกอิน ไม่มีการใช้ token ในแอป
- ไม่สอนเรื่องขั้นสูง (rebase, cherry-pick, GitHub Actions, submodule) นอกจากบอกชื่อไว้ใน "อยากรู้ลึก"
- ไม่ทำวิชา Cybersecurity หรือ CCNP ในรอบนี้ (แต่โครงในข้อ 7 ต้องรองรับการเพิ่มวิชาภายหลัง)

## 9. การตัดสินใจของผู้เขียนเอกสาร (ผู้ใช้ตรวจได้)

- โครงหลายวิชาในข้อ 7 รวมถึงหน้าเลือกวิชาและการแยกความคืบหน้า ผู้ใช้เห็นด้วยในแชตแล้ว ส่วนรายละเอียดเป็นการตัดสินใจของผู้เขียนเอกสาร
- เครื่องจำลองคำสั่งเป็นแบบง่าย จำลองเฉพาะพฤติกรรมที่บทเรียนใช้ ผลที่แสดงต้องตรงกับ git จริงในกรณีที่สอน (ข้อความ output ย่อได้ แต่ห้ามผิดความหมาย)
- ใช้ `git switch` เป็นคำสั่งหลักสำหรับเปลี่ยน branch และบอกไว้ว่า `git checkout` ทำได้เหมือนกัน เพราะคลิปเก่าๆ ใช้ checkout
- ใช้ branch ชื่อ `main` เป็นค่าเริ่มต้น ตามค่าเริ่มต้นของ GitHub
- สอนการล็อกอินตอน push ผ่านหน้าต่างของ Git Credential Manager ที่ติดมากับ Git for Windows ส่วน SSH key ใส่ไว้ใน "อยากรู้ลึก"
- วิชานี้เริ่มสร้างหลังจากผู้ใช้ลองเรียนบท CCNA ใหม่แล้ว (งานที่ 9 ของแผนเดิม) เพื่อเอาความเห็นมาปรับวิธีสอนก่อน
