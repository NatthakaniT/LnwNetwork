# พื้นฐานก่อนเสมอ (Foundations first) — เอกสารออกแบบ

วันที่: 2026-10-27
สถานะ: ร่าง รอผู้ใช้อนุมัติ
ต่อจาก: `2026-10-24-ccna-learning-app-design.md` และ `2026-10-25-ui-refresh-design.md` (กฎเนื้อหา ภาษา และหน้าตาเดิมยังใช้ทั้งหมด ยกเว้นข้อที่เอกสารนี้เปลี่ยน)

## 1. ทำไม

ในอีก session หนึ่ง ผู้ใช้วิเคราะห์แอป Astra AI (astra-ai.co) และลองต้นแบบบทเรียน subnet mask 2 หน้า (`C:\ProjectX\REA\spike\subnet-mask.html`, `C:\ProjectX\REA\spike\bits-switches.html`) สิ่งที่พบ:

- ต้นแบบ subnet mask เขียนว่า "IP มี 32 ช่อง (32 bit)" ผู้ใช้งงตั้งแต่ประโยคนั้น เพราะยังไม่เคยเรียนว่า bit คืออะไร ต้นแบบข้ามพื้นฐานไปเอง
- พอได้กดสวิตช์ไฟ 8 ตัวเอง แล้วเห็นว่า 128 + 64 = 192 ผู้ใช้เริ่มเห็นภาพ จากนั้นถาม "ทำไม" ต่อกันเป็นชั้น: ทำไมต้องจองสวิตช์ 8 ตัว → สวิตช์หน้าตาเป็นยังไง → 8 ตัวพอดีกับตัวอักษรยังไง
- ผู้ใช้บอกเองว่า "ผมเป็นคนที่เข้าใจอะไรยาก อยากเข้าใจพื้นฐานก่อน ทุกอย่างต้องดูแล้ว make sense กัน" และ "อยากรู้การทำงานพื้นฐานตั้งแต่ต้น ของทุกบท ทุกอย่าง"
- ผู้ใช้ยืนยันว่า **คลิป 9hua ยังเป็นสิ่งที่ทำให้เห็นภาพและเข้าใจได้มากที่สุด**

ตัวอย่างปัญหาเดียวกันที่อยู่ในแอปตอนนี้: บท p0-l4 ฉาก 3 บอกว่า IPv4 "แต่ละชุด เป็นเลข 0 ถึง 255" แต่ไม่ได้บอกว่าทำไมต้อง 255 ซึ่งต้องรู้เรื่อง bit กับ byte ก่อน

## 2. สิ่งที่ผู้ใช้ตัดสินใจแล้ว

1. **คลิป 9hua ยังเป็นขั้นแรกและเป็นตัวหลักของทุกบท** ส่วนที่เพิ่มในเอกสารนี้เป็นตัวเสริม ไม่ได้แทนคลิป
2. **พื้นฐานก่อนจริงๆ ทุกบท:** ทุกบทต้องอธิบายว่า "สิ่งนี้ทำงานยังไงตั้งแต่ต้น" ก่อนถึงรายละเอียด และห้ามใช้ความรู้ที่ยังไม่ได้สอน (กฎข้อ 7.5 เดิม ตอนนี้บังคับเข้มขึ้น ดูข้อ 4)
3. **ไม่จำกัดเวลาแล้ว** (เดิมจะสอบภายในปลายพฤศจิกายน 2026) จึงไม่ต้องเรียงบทตามน้ำหนักข้อสอบอีก (spec เดิมข้อ 11.2) ให้เรียงตามลำดับที่ต้องรู้ก่อน-หลังแทน
4. **ทุกบทมีตัวอย่างจากชีวิตประจำวัน** (เหมือนเดิม) เช่น ทอนเงินด้วยแบงก์ = เลขฐานสอง, เบอร์ห้องคอนโด 1205 = ชั้น + ห้อง = network + host
5. **เอา "สอบข้ามบท" ออก** (spec เดิมข้อ 11 "ข้ามบทได้ด้วยสอบข้ามบท") ทุกบทปลดล็อกตามลำดับเท่านั้น ต้องลบปุ่มในแผนที่บทเรียน, หน้า "สอบข้ามบท" ใน LessonPage, ข้อความแจ้งเตือนใน App, ส่วนของ progress ที่บันทึกการข้ามบท และ test ที่เกี่ยวข้อง
6. **แก้ข้อมูลเดิม:** ผู้ใช้**ไม่เคยเรียน ITN/SRWE** ข้อความใน spec เดิม (ข้อ 1, 6.3 และ 11) ที่บอกว่าเคยเรียนหรือเคยเห็นสไลด์ NetAcad ไม่ถูกต้อง ห้ามเขียนเนื้อหาโดยถือว่าผู้ใช้รู้เรื่องใดมาก่อน
7. **ใช้ครูถามตอบใน Claude.ai Project** ซึ่งรวมอยู่ในแพ็กเกจที่ผู้ใช้มีอยู่แล้ว ไม่ใส่ AI ในแอป ยังใช้ฟรีทั้งหมดตามข้อจำกัดเดิม

## 3. บทเรียนแบบใหม่

ขั้นที่มีอยู่แล้ว ใส่คำว่า "เดิม" ไว้:

0. **เช็กพื้นฐาน (ใหม่):** คำถามสั้น 2–3 ข้อเรื่องที่บทนี้ต้องใช้ ถ้าตอบผิด บอกว่าขาดเรื่องไหน พร้อมลิงก์ไปบทนั้น ผู้ใช้เลือกได้ว่าจะไปทบทวนก่อน หรือเรียนต่อเลย ไม่บังคับ
   มีกล่อง **"เรื่องนี้ต่อจาก…"** บอกว่าบทนี้ใช้ความรู้จากบทไหน และใช้เรื่องอะไร
1. **คลิป 9hua** (เดิม)
2. **ภาพเคลื่อนไหวทบทวน** (เดิม) + **ลองกดเอง (ใหม่):** หลังจากดูฉาก มีของให้กดเล่นที่ผลเปลี่ยนทันทีตามที่กด เพื่อเช็กว่าเห็นภาพเดียวกับคลิป ใช้เฉพาะบทที่มีตัวเลขหรือกลไกให้ลอง เช่น แผงสวิตช์ 8 ตัว (bit/byte), แปลงเลขฐาน, แถบเลื่อน /24–/30 กับภาพที่อยู่ 256 ช่อง (Subnet), AND ระหว่าง IP กับ mask เป็นต้น บทที่ไม่มีกลไกแบบนี้ไม่ต้องมี
3. **ห้องทดลอง** (เดิม)
4. **คำถาม 2 ชั้น** (เดิม)

ที่หน้าบทเรียน (ไม่ใช่ขั้น):
- **กล่อง "อยากรู้ลึก"** สำหรับเรื่องที่ลึกกว่าที่ CCNA ต้องใช้ เช่น transistor หรือตาราง ASCII เปิดอ่านได้ บอกชัดว่าไม่ต้องรู้ก็เรียนต่อได้
- **ปุ่ม "คัดลอกไปถามครู":** คัดลอกข้อความแบบ "ผมเรียนถึงบท [ชื่อ] ขั้น [ขั้น] ตอบข้อ [คำถาม] ผิด อยากถาม…" ไปวางใน Claude.ai

## 3.1 ภาพเคลื่อนไหวแบบใหม่ (ผู้ใช้ลองต้นแบบแล้ว บอกว่า "เข้าใจมากขึ้น")

ต้นแบบ: `C:\ProjectX\REA\spike\arp-scene.html` (ฉาก ARP ทำใหม่เป็น 6 ขั้น) ใช้เป็นมาตรฐานของภาพเคลื่อนไหวทุกบท

ปัญหาที่เจอในภาพเคลื่อนไหวเดิม (ดูจากเว็บจริง บท p0-l1 และ p0-l4):
- ของบนเวทีซ้อนกัน ของจากฉากก่อนยังค้างอยู่ ซองไปจอดทับหน้าจอคอม
- คำถามกับคำตอบโผล่พร้อมกัน (p0-l4 ฉาก ARP) ทำให้ลำดับเรื่องหายไป
- ความหมายจริงอยู่ในตัวหนังสือ ภาพไม่ได้บอกว่าในซองเขียนอะไร หรือเครื่องรู้อะไรอยู่
- broadcast กับ unicast ใช้ซองแบบเดียวกัน
- กด "ฉากต่อไป" แล้วภาพกระโดดไปตอนจบ ไม่มีร่องรอยว่าของวิ่งไปทางไหน
- ตัวหนังสือบนเวทีเล็กและจาง

กฎของภาพเคลื่อนไหวแบบใหม่ (ทุกฉากต้องผ่าน):
1. **แถบ "ในชีวิตจริง"** อยู่เหนือเวที ทุกฉากมีประโยคชีวิตจริงคู่กับสิ่งที่เกิดในเครือข่าย
2. **1 ฉาก = 1 เหตุการณ์** ห้ามโผล่ผลลัพธ์ก่อนเหตุ แต่ละฉากมีชื่อสั้น (เช่น "ตะโกนถาม") แสดงเป็นปุ่มเลือกฉาก กดย้อนหรือกดข้ามได้
3. **เวทีเริ่มใหม่ทุกฉาก** เห็นเฉพาะของที่ฉากนั้นใช้ ไม่มีของค้างจากฉากก่อน
4. **เห็นสิ่งที่อุปกรณ์รู้** เช่น ARP table, MAC table ของ Switch, routing table แสดงเป็นสมุดหรือตารางที่เห็นตอนว่าง และเห็นตอนถูกเขียนลงไป
5. **ของที่วิ่งมีป้ายหน้าซอง** บอกข้อมูลสำคัญที่อุปกรณ์ใช้ตัดสินใจ (ถึงใคร, ถามอะไร, MAC/IP ผู้รับ)
6. **สีบอกชนิดการส่ง ใช้ชุดเดียวกันทั้งคอร์ส** ถามทุกเครื่อง (broadcast) = ส้ม, ตอบเครื่องเดียว (unicast) = ฟ้า, ส่งข้อมูลจริง = สีของภาค มีคำอธิบายสีใต้เวที
7. **ทางที่วิ่งผ่านค้างเป็นเส้น** หยุดภาพหรือข้ามมาที่ฉากไหน ก็เห็นสภาพตอนจบของฉากนั้นครบ รวมเส้นทาง
8. **เครื่องที่ไม่เกี่ยวจางลงพร้อมป้ายพูดสั้นๆ** (เช่น "ไม่ใช่ฉัน") ส่วนเครื่องที่เกี่ยวจะเรืองขึ้นมา
9. **ห้ามของทับกัน** ป้ายชื่อของอุปกรณ์ที่เรียงในแนวตั้งให้อยู่ข้างไอคอน และซองต้องจอดข้างอุปกรณ์ ไม่จอดทับ
10. ตัวหนังสือบนเวทีต้องอ่านง่าย (ขนาดและ contrast ตาม ui-refresh spec)

**เรื่อง 3D:** ยังไม่ใช้ในรอบนี้ เพราะเรื่องเครือข่ายเป็นลำดับเหตุการณ์ (ใครส่งอะไรหาใคร อุปกรณ์รู้อะไร) ภาพ 2D แบบเป็นขั้นตอนอ่านง่ายกว่า และ 3D ทำให้มุมกล้องบังของได้ 3D แบบเบาจะใช้ภายหลัง เฉพาะเรื่องที่มีชั้นจริงๆ เช่น ตึกคอนโดในบท Subnet หรือการห่อพัสดุเป็นชั้นของ OSI (เป็นการตัดสินใจของผู้เขียนเอกสาร ซึ่งผู้ใช้เห็นด้วยแล้วตอนลองต้นแบบ)

## 4. กฎ "พื้นฐานก่อน" ที่ตรวจได้

1. ทุกบทประกาศ `requires` (บทที่ต้องรู้ก่อน) และ `introduces` (ศัพท์หรือแนวคิดที่บทนี้สอน)
2. ศัพท์ใน glossary ทุกคำบอกได้ว่าบทไหนสอนครั้งแรก ห้ามใช้ศัพท์ในบทพูด คำบรรยาย หรือคำถามก่อนบทที่สอน (ต่อยอดข้อ 4 ใน `round1-handoff.md` ที่ให้ RichText ใช้ศัพท์ที่สอนมาแล้ว) ต้องมี test ตรวจ
3. ทุกตัวเลขหรือข้อจำกัดที่บอกผู้เรียน (เช่น 0–255, 32 bit, 48 bit, ลบ 2) ต้องมีฉากหรือกล่องที่บอกว่า "ทำไม" อยู่ในบทนั้น หรือในบทก่อนหน้าที่อยู่ใน `requires`
4. แต่ละบทเปิดด้วยคำถาม "สิ่งนี้มีไว้แก้ปัญหาอะไร" ก่อนอธิบายวิธีทำงาน

## 5. ตรวจย้อนภาค 0 และปรับลำดับ

- ตรวจบท p0-l1 ถึง p0-l5 ที่เสร็จแล้วด้วยกฎข้อ 4 แก้จุดที่ใช้ความรู้ก่อนสอน ที่เห็นแล้วคือ p0-l4 ฉาก 3 (0–255) และหมายเหตุใน handoff เรื่อง MAC "48 บิต"
- **เพิ่มบทใหม่ในภาค 0 ก่อน p0-l4:** "คอมพูดภาษา 0 กับ 1" สอน bit, byte, ทำไม 8, ทำไม 0–255, เลขฐานสองเบื้องต้น ใช้ต้นแบบ `bits-switches.html` เป็นฐานของขั้น "ลองกดเอง" ตัวอย่างชีวิตจริงคือสวิตช์ไฟกับทอนเงินด้วยแบงก์ ส่วนบท "เลขฐานสอง" ในภาค 1 เปลี่ยนเป็นฝึกแปลงเลขให้คล่องและใช้กับ IP
- การเพิ่มบทในภาค 0 ทำให้ลำดับเปลี่ยน จึง**ต้องทำ "ตรึง lesson id" (handoff ข้อ 5) ก่อน** เพราะความคืบหน้า (localStorage) และโฟลเดอร์เสียง `public/audio/p0-lN/` ผูกกับ id
- ภาคหลัง (1–6) เรียงตามลำดับที่ต้องรู้ก่อน-หลัง ไม่ต้องเรียงตามน้ำหนักข้อสอบ ลำดับบทในภาค 1 ตอนนี้ใช้ได้ (เลขฐานสอง → IPv4 → Subnet → ฝึก Subnetting → …) ผู้สร้างตรวจซ้ำได้ตาม `requires`

## 7. ไม่ทำในรอบนี้

- ไม่ใส่ AI หรือ API ในแอป
- ไม่ทำแบบจำลอง 3D หรือแกลเลอรี Lab แบบ Astra (ดูข้อ 3.1)

## 8. ลำดับการสร้าง (ผู้เขียนเอกสารเสนอ)

1. ตรึง lesson id (handoff ข้อ 5) และเอา "สอบข้ามบท" ออก
2. โครงข้อมูล `requires`/`introduces` + test กฎข้อ 4.1–4.2
3. ขั้น "เช็กพื้นฐาน" + กล่อง "เรื่องนี้ต่อจาก…" + กล่อง "อยากรู้ลึก" + ปุ่ม "คัดลอกไปถามครู"
4. ชนิดกิจกรรม "ลองกดเอง" ในขั้นที่ 2 (เริ่มจากแผงสวิตช์ 8 bit)
4.5 เครื่องเล่นฉากแบบใหม่ตามข้อ 3.1 แล้วทำฉาก ARP ของ p0-l4 ใหม่เป็นบทแรกที่ใช้
5. บทใหม่ "คอมพูดภาษา 0 กับ 1" ครบทุกขั้น พร้อมเสียง (F5-TTS เดิม)
6. ตรวจย้อนและแก้ภาค 0 (รวมทำฉากทุกฉากของภาค 0 ให้ผ่านกฎข้อ 3.1)

8. ให้ผู้ใช้ลองบทใหม่จริงแล้วเก็บความเห็น (spec เดิมข้อ 11.4) ก่อนเริ่มภาค 1

งานรอบ 2 อื่นใน `round1-handoff.md` (ข้อ 1–4, 6) ยังต้องทำ ให้ทำก่อนเขียนเนื้อหาภาค 1 เหมือนเดิม

## 9. การตัดสินใจของผู้เขียนเอกสาร (ผู้ใช้ตรวจได้)

- ขั้นเช็กพื้นฐานไม่บังคับ: ตอบผิดแล้วแค่แนะนำบทที่ต้องทบทวน ไม่ล็อกบท เพราะบทถูกปลดล็อกตามลำดับอยู่แล้ว
- บทแรกของคอร์ส (p0-l1) ไม่มีขั้นเช็กพื้นฐาน
- คำถามเช็กพื้นฐานใช้ภาษาไทยชั้นเดียว ไม่มีชั้นอังกฤษ
- "ลองกดเอง" อยู่ในขั้นที่ 2 ต่อจากฉาก ไม่แยกเป็นขั้นที่ 5 เพื่อไม่ให้แท็บขั้นยาวขึ้น
- บทใหม่ใส่ในภาค 0 ไม่ใช่ย้ายบท "เลขฐานสอง" ทั้งบทขึ้นมา เพราะภาค 0 ตั้งใจให้ไม่มีศัพท์ยาก บทใหม่เน้นสวิตช์และตัวอย่างชีวิตจริง ส่วนการแปลงเลขยังอยู่ภาค 1
- ป้าย "ตรงกับ Cisco" (`ciscoModules`) คงไว้แบบเดิม ใช้เป็นที่อ้างอิงเวลาไปหาอ่านต่อ แม้ผู้ใช้ไม่เคยเรียน NetAcad ก็ไม่เป็นปัญหา
- ความคืบหน้าเดิมที่บันทึกว่า "ข้ามบท" ไว้ในเครื่อง ให้นับเป็นยังไม่ผ่าน เพื่อให้กลับไปเรียนบทนั้นจริง
- โค้ดต้นแบบใน `C:\ProjectX\REA\spike\` ใช้เป็นแค่แนวคิดและหน้าตา เขียนใหม่ด้วย component และ token ของแอปนี้
