# ตรวจย้อนภาค 0 (p0-l1 ถึง p0-l5)

ผลจาก Task 2 ของแผน foundations-first ยังไม่ได้แก้เนื้อหา (แก้ใน Task 7) ตรวจตามกฎ spec ข้อ 4

## ก. error ที่ `validateCourse` เจอจริง (กฎข้อ 4.2 ศัพท์ก่อนสอน)

เจอ 3 รายการ (Cable 1, Data 2) ตรวจจากข้อความที่ผู้เรียนเห็น เทียบกับบทที่ใส่ศัพท์นั้นใน `terms` เป็นบทแรก

- `บท p0-l1: ใช้ศัพท์ "Cable" ก่อนบทที่สอน (p0-l2)` มาจากตัวเลือกคำถามภาษาอังกฤษ (`It is one cable that connects two computers...` ที่ p0-l1.ts บรรทัด 292) บทพูดภาษาไทยใช้ "สาย" ไม่ติด ทางแก้: ให้ p0-l1 ใส่ `cable` ใน `terms` หรือเลี่ยงคำนี้ในคำถาม
- `บท p0-l1: ใช้ศัพท์ "Data" ก่อนบทที่สอน (p0-l5)` มาจากข้อความคำถามภาษาอังกฤษ (`It can only send data using wireless signals.` ที่ p0-l1.ts บรรทัด 277)
- `บท p0-l2: ใช้ศัพท์ "Data" ก่อนบทที่สอน (p0-l5)` มาจากคำถามภาษาอังกฤษ (`forward data between different networks`, `send data to other networks` ที่ p0-l2.ts บรรทัด 311 และ 345)

หมายเหตุ: p0-l5 สอน "Data" เป็นชื่อชั้นในสุดของการห่อ (data → segment → packet → frame → bits) แต่ p0-l1 และ p0-l2 ใช้คำว่า data ในความหมายทั่วไป "ข้อมูล" ทางแก้ที่เป็นไปได้ใน Task 7 คือ (ก) เอา `data` ออกจาก `terms` ของ p0-l5 แล้วให้บทแรกที่พูดถึง "ข้อมูล" สอนแทน หรือ (ข) ให้ p0-l1 สอนคำว่า data และ p0-l5 บอกว่าเป็นชั้นในสุด เลือกทางไหนให้ดูตอนแก้ภาค 0 บทพูดภาษาไทย (`narrationTh`) ไม่ติด เพราะใช้คำว่า "ข้อมูล"

ศัพท์อื่นผ่านหมด: mac, ip, ipv4, lan, wan, switch, router, gateway, dns, arp, packet ฯลฯ ถูกสอนก่อนหรือในบทเดียวกับที่ใช้

## ข. ผลอ่านทีละบท ตามกฎ 4.3 และ 4.4 (เครื่องตรวจไม่ได้)

กฎ 4.3 = ทุกตัวเลขหรือข้อจำกัดต้องมีคำอธิบาย "ทำไม" · กฎ 4.4 = เปิดบทด้วยปัญหาที่สิ่งนี้แก้

### p0-l1 Network คืออะไร
- 4.4 ผ่าน เปิดด้วยบ้านสองหลังไม่มีถนน แล้วถามว่า "จะส่งยังไงดี"
- 4.3 ผ่าน ไม่มีตัวเลขหรือข้อจำกัด ที่ต้องอธิบาย (เหตุผลที่ต้องมี network มีในฉากรองสุดท้าย)

### p0-l2 อุปกรณ์มีอะไรบ้าง
- 4.4 ไม่ผ่านบางส่วน เปิดด้วย "จำได้ไหมครับ บ้านคือเครื่อง" เป็นการทบทวนคำจากบทก่อน ปัญหาจริง (ต่อคอมเป็นทอดแล้วสายขาด หมู่บ้านเดียวกันส่งเองได้ ข้ามหมู่บ้านไม่ได้) มาที่ฉากสามเป็นต้นไป ควรเปิดด้วยปัญหา "ต่อคอมหลายเครื่องเข้าหากันยังไง"
- 4.3 ผ่านบางส่วน "ช่องเสียบสายแลนช่องเดียว" มีเหตุผล (ทำไมต้องมี Switch) แต่เลขที่อยู่ที่ใช้ตัดสินว่าต้องออกนอกหมู่บ้านถูกเลื่อนไปบทที่สี่ ("เดี๋ยวบทที่สี่เล่า") ยอมรับได้เพราะบอกชัดว่าเล่าทีหลัง

### p0-l3 ข้อมูลเดินทางยังไง
- 4.4 ผ่าน เปิดด้วยย้ายของทั้งห้อง ส่งก้อนเดียวไม่ไหว จึงแบ่งเป็นกล่อง
- 4.3 ผ่าน มีสองข้อว่าทำไมต้องแบ่ง (ใช้ถนนร่วมกันได้ และส่งใหม่เฉพาะกล่องที่หาย) และมีเหตุผลว่าทำไมทุกกล่องต้องมีที่อยู่ผู้ส่งและผู้รับ

### p0-l4 ที่อยู่ 2 แบบ: MAC กับ IP
- 4.4 ผ่านบางส่วน เปิดด้วยเลขบัตรประชาชนกับบ้านเลขที่ เป็นภาพเปรียบ ไม่ใช่คำถาม "ทำไมต้องมีที่อยู่สองแบบ" (คำตอบอยู่ฉากห้า) ควรเปิดด้วยปัญหาก่อน
- 4.3 ไม่ผ่าน (จุดที่ spec เห็นแล้ว)
  - ฉากที่สาม (IP) บอก "แต่ละชุด ศูนย์ ถึง สองร้อยห้าสิบห้า" และป้าย "เลข 0 ถึง 255" โดยไม่บอกว่าทำไมสูงสุดคือ 255 (เพราะแต่ละชุดคือ 8 bit; ยังไม่มีบทสอน bit) ต้องรอบทใหม่ p0-bits ก่อน p0-l4 หรือบอกเหตุผลในบทนี้
  - "เลข 4 ชุด" ไม่บอกว่าทำไม 4 (4 ชุด x 8 bit = 32 bit)
  - ป้าย MAC "เลข 0-9 กับตัว A-F รวม 12 ตัว" ไม่บอกว่าทำไมใช้ A-F และทำไม 12 ตัว (ฐานสิบหก, 48 bit) ตรงกับหมายเหตุ "48 บิต" ใน handoff
  - noteTh ของคลิปพูด "แต่ละชุด 0 ถึง 255" เช่นกัน
  - ป้ายฉากข้ามหมู่บ้าน "ส่วนหนึ่งของ IP บอกหมู่บ้าน · ส่วนไหน เดี๋ยวภาค 1 เล่า" ยอมรับได้ เพราะบอกว่าเล่าทีหลัง

### p0-l5 การห่อของเป็นชั้น ๆ
- 4.4 ไม่ผ่าน เปิดด้วยห่อของขวัญเป็นชั้น ๆ ก่อน ปัญหาที่ต้องแยกชั้น (เปลี่ยนชั้นหนึ่งไม่ต้องรื้อชั้นอื่น) มาที่ฉากเจ็ด ควรเปิดด้วยปัญหา เช่น "เปลี่ยนจากสายแลนเป็นไวไฟ ต้องรื้อทุกอย่างไหม"
- 4.3 ไม่ผ่านบางส่วน "OSI เจ็ดชั้น, TCP/IP สี่ชั้น" ไม่บอกว่าทำไมแบ่งเท่านั้น ยอมให้เป็นข้อมูลที่ต้องจำสำหรับข้อสอบได้ ถ้าจะบอกว่าเป็นข้อตกลงมาตรฐาน ควรพูดตรง ๆ ว่า "เป็นข้อตกลง ไม่มีสูตร" และฉากสุดท้ายกล่าวถึง bits ก่อนบท p0-bits (คำว่า "bits" ในฉากห้า "ทีละนิด เรียกว่า bits") ถ้าบทใหม่มาก่อนจะเชื่อมกันได้
- ฉากหกถึงแปดมีเลขชั้น 1–4 และ 2/3/4 ตามหัวข้อสอบ ไม่ติดกฎ 4.3 เพราะบอกว่านับจากถนนขึ้นไป

## สถานะหลัง Task 7b (เพิ่มบท p0-bits "คอมพูดภาษา 0 กับ 1" ระหว่าง p0-l3 กับ p0-l4)

- p0-l4 4.3 "0 ถึง 255" (ฉาก s3, ป้าย iLbl3, noteTh คลิป): แก้แล้ว บทพูด s3 บอกว่าแต่ละก้อนคือ 1 byte ป้าย iLbl3 "ก้อนละ 1 byte จึงเป็น 0 ถึง 255 · รวม 32 bit" noteTh บอกว่าแต่ละชุดคือ 1 byte และ p0-l4 มี `requires` ไป p0-bits
- p0-l4 4.3 "เลข 4 ชุด" ทำไม 4: แก้แล้ว 32 bit ตัดเป็น 4 ก้อน ก้อนละ 1 byte (s3 และป้ายสรุป sum2 "IPv4 = 32 bit") p0-bits ฉาก s9 เล่าเต็ม
- p0-l4 4.3 MAC "0-9 กับ A-F รวม 12 ตัว": แก้แล้ว ฉากใหม่ s2b "MAC 48 bit": 48 bit = 6 byte, เขียนทีละ 4 bit, 4 bit มี 16 แบบ, 0-9 ไม่พอ เลยเพิ่ม A-F, 48 ÷ 4 = 12 ตัว glossary `mac-address` ใส่ "48 bit" แล้ว (เรื่องจาก handoff)
- p0-l5 "bits" ก่อนบท p0-bits: แก้แล้ว p0-bits มาก่อนแล้ว บทพูด s5 พูดว่า "ทีละ bit เรียกว่า bits" glossary `bits` เชื่อมกับ bit
- p0-l2 "เดี๋ยวบทที่สี่เล่า" (s8 และ lab intro) กับ p0-l3 noteTh "บทที่ 4": แก้แล้ว เลิกเรียกเลขบท ใช้ "บทหลัง" หรือชื่อบท "ที่อยู่ 2 แบบ" มี test กันไม่ให้ข้อความในบทเรียกบทด้วยเลข
